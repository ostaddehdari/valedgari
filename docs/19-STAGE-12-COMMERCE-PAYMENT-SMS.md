# تحویل استیج ۱۲ — سفارش، فاکتور، زرین‌پال و IPPanel

تاریخ تحویل: ۸ آبان ۱۴۰۵ (۳۰ اکتبر ۲۰۲۶)

## نتیجه اجرایی

استیج ۱۲ با ۱۰ ورک کامل شد. چرخه تجاری دوره از انتخاب دوره تا ساخت سفارش، اعمال حمایت سازمانی، صدور فاکتور، انتقال به زرین‌پال، Verify، ثبت‌نام، رسید، تاریخچه مالی، بازپرداخت و گزارش تطبیق ساخته شده است. پیامک‌ها نیز از درخواست وب جدا و در Outbox دارای Idempotency، Retry و سقف تلاش ثبت می‌شوند.

اتصال واقعی سرویس‌های بیرونی به Credential معتبر نیاز دارد. در محیط فاقد کلید، پرداخت یا پیامک موفق اعلام نمی‌شود. حالت آزمایشی داخلی فقط در `TestConfig` فعال است و در Production خاموش می‌ماند.

| 12.2 | ثبت‌نام رایگان | سفارش و فاکتور صفر، Audit، Enrollment و پیام ثبت‌نام بدون درگاه و به‌شکل Idempotent ساخته می‌شود. |
| 12.3 | فاکتور و رسید | شماره یکتا، ریز مبلغ، سهم سازمان/والد، پیگیری و نسخه مناسب چاپ یا ذخیره PDF نمایش داده می‌شود. |
| 12.4 | دوره‌های من | دوره فعال/تکمیل‌شده، ادامه درس، پیشرفت و لینک فاکتور در داشبورد والد قرار دارد. |
| 12.5 | تاریخچه مالی | سفارش، فاکتور، تراکنش، حمایت، لغو و بازپرداخت فقط برای مالک قابل مشاهده است. |

## مدل داده افزوده‌شده

- `CourseOrder` و `CourseOrderItem`: سفارش، اقلام و Snapshot قیمت؛
- `CourseInvoice`: فاکتور یک‌به‌یک با سفارش؛
- `PaymentTransaction`: Authority، کلید Idempotency، RefID، وضعیت و پاسخ پاک‌سازی‌شده؛
- `IntegrationSetting`: تنظیم عمومی و Secret رمز‌شده همراه با Hint؛
- `SmsOutbox`: رویداد، گیرنده، Pattern، Payload، وضعیت، Retry و شناسه Provider؛
- `CommerceAuditLog`: رویدادهای مالی بدون ثبت Secret.

`CourseEnrollment` نیز به سفارش متصل شده است تا منشأ رایگان، خرید شخصی یا حمایت سازمانی قابل ممیزی باشد.

## منطق حمایت سازمانی

Checkout طرح‌های فعال همان والد را با دوره تطبیق می‌دهد. تطبیق می‌تواند با `course:<id>`، نامک دوره، عنوان دوره، `all_courses`، «همه دوره‌ها» یا `*` انجام شود. سپس این کنترل‌ها اجرا می‌شوند:

- فعال‌بودن سازمان، طرح و قرارداد؛
- بازه زمانی طرح؛
- بودجه باقی‌مانده؛
- سقف تجمعی حمایت هر والد؛
- درصد یا مبلغ ثابت حمایت؛
- رزرو `PaymentAllocation` هم‌زمان با سفارش؛
- آزادسازی رزرو هنگام لغو یا جایگزینی شیوه پرداخت.

برای حمایت ۱۰۰٪، سفارش بدون درگاه تکمیل می‌شود. برای حمایت ۷۰/۳۰ فقط سهم والد به زرین‌پال ارسال می‌شود و هر دو سهم روی فاکتور باقی می‌مانند.

## امنیت پرداخت و Secret

- Secretها با nonce تصادفی، جریان کلید مشتق‌شده و MAC مستقل به‌صورت Encrypt-then-MAC نگهداری می‌شوند.
- مقدار کامل Secret پس از ثبت به رابط کاربری بازگردانده نمی‌شود.
- Payload ثبت‌شده در Audit و تراکنش، Merchant و Token را حذف می‌کند.
- مبلغ داخلی تومان و مبلغ درخواست زرین‌پال ریال است؛ تبدیل فقط در مرز Provider انجام می‌شود.
- Callback فقط Authority ذخیره‌شده را می‌پذیرد و Verify را سمت سرور انجام می‌دهد.
- کدهای ۱۰۰ و ۱۰۱ در Verify پذیرفته و Callback تکراری بدون ساخت Enrollment دوم پاسخ داده می‌شود.
- مشاهده فاکتور با مالکیت سفارش کنترل و شناسه خانواده دیگر با 404 پاسخ داده می‌شود.

## پیامک و Retry

رویدادهای `course_enrolled`، `purchase_success`، `course_completed`، `course_reminder` و `payment_failed` پشتیبانی می‌شوند. Pattern Code برای هر رویداد مستقل است. اگر Pattern تعریف نشده باشد، متن Webservice ارسال می‌شود.

پردازش صف با فرمان زیر انجام می‌شود:

```bash
flask --app wsgi:app process-sms --limit 50
```

این فرمان برای اجرای تکراری در cron یا systemd timer امن است. هر رویداد `unique_key` دارد؛ پیام ارسال‌شده دوباره ارسال نمی‌شود و خطا حداکثر پنج تلاش با فاصله افزایشی خواهد داشت.

## آزمون پذیرش

مجموعه آزمون پروژه پس از تحویل این استیج: **۸۴ آزمون موفق**.

پوشش اختصاصی شامل محرمانگی و تشخیص دستکاری Secret، فاکتور صفر، Audit و پیامک ثبت‌نام رایگان، پرداخت آزمایشی و Verify تکراری، لغو Callback، حمایت ۷۰/۳۰، حمایت ۱۰۰٪، IDOR فاکتور، مخفی‌بودن Token، ارسال آزمایشی IPPanel، Idempotency صف پیامک، CSV فروش و بازپرداخت است.

تمام فایل‌های Python، JavaScript و قالب‌های Jinja نیز جداگانه بررسی می‌شوند.

## وابستگی پیش از Production

- Merchant ID معتبر زرین‌پال؛
- انتخاب Sandbox یا Production؛
- Callback عمومی `https://srun.ir/valedgari/dashboard/payments/zarinpal/callback`؛
- API Token و شماره ارسال IPPanel؛
- Pattern Codeهای تأییدشده پنل پیامک؛
- یک پرداخت کم‌مبلغ و یک پیامک واقعی در Staging پیش از انتشار عمومی.

## وضعیت استقرار

طبق تصمیم پروژه، استیج ۱۲ جداگانه روی سرور نصب نشده است. نصب Production پس از تکمیل استیج‌های ۱۳ تا ۱۵ و اجرای Migration، Backup و Smoke Test یکپارچه انجام خواهد شد.
